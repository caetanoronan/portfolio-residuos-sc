📋 Introdução ao Projeto

🎯 Objetivo Principal: Desenvolver análise territorial integrada da geração de resíduos sólidos em Santa Catarina utilizando bacias hidrográficas como unidade de planejamento ambiental.
🌊 Base Legal: Lei 9.433/1997 (Política Nacional de Recursos Hídricos)

A PNRH define a bacia hidrográfica como unidade territorial para implementação da Política Nacional de Recursos Hídricos. Integrar gestão de resíduos com bacias permite planejamento ambiental integrado, considerando que resíduos mal gerenciados podem contaminar recursos hídricos.

🔍 Problema Identificado

Gestão Fragmentada

Falta de integração entre gestão de resíduos e recursos hídricos

Dados Dispersos

Informações censitárias não organizadas por bacias hidrográficas

Visualização Limitada

Ausência de ferramentas interativas e acessíveis para análise territorial

💻 Processo de Desenvolvimento

📐 Pipeline de Dados (5 Etapas)

1️⃣ Carregar Dados Censitários

Fonte: SC_setores_CD2022.gpkg (16.831 setores)

Sistema: SIRGAS 2000 / UTM 22S (EPSG:31982)

gdf = gpd.read_file('SC_setores_CD2022.gpkg')

2️⃣ Fetch População (IBGE API)

Padrão: Projeções → Agregados → Fallback local

Timeout: 60 segundos por request

3️⃣ Calcular Resíduos

Fórmula: População × 0,95 kg/hab/dia × 365 ÷ 1000 = t/ano

waste = (pop * 0.95 * 365) / 1000

4️⃣ Agregar por Território

Método: GeoPandas dissolve(by='field', aggfunc='sum')

Níveis: Setor → Município → Bacia → Região

5️⃣ Gerar Visualizações

Outputs: Folium (mapas) + Plotly (dashboards)

Destino: analise_exploratoria/outputs/

🌊 Integração de Bacias Hidrográficas

Dual-Source Pattern (Inovação do Projeto):
  1. Verifica arquivo local em data/ (formatos: .gpkg, .geojson, .shp, .zip, .fgb)
  2. Se não encontrar, faz download via ArcGIS REST API (layers 0-6)
  3. Realiza spatial join por área máxima de overlap
  4. Atribui cada Ottobacia a 1 das 8 macro-bacias

❓ Perguntas Antecipadas

Por que 0,95 kg/hab/dia?

Resposta: Taxa média nacional (ABRELPE). Poderia ser refinada com dados locais futuros.

Como garantir que API não falhe?

Resposta: Sistema de fallback em 3 camadas + verificação de arquivo local primeiro.

Por que bacias hidrográficas?

Resposta: Integração gestão ambiental (Lei 9.433/1997 - PNRH) + facilita políticas territoriais integradas.

GitHub Copilot ajudou muito?

Resposta: Sim! Acelerou desenvolvimento, sugeriu boas práticas, gerou código boilerplate automaticamente.

⚠️ Limitações do Estudo

Taxa Uniforme

0,95 kg/hab/dia não considera variações urbano/rural, nível socioeconômico ou sazonalidade

Snapshot Temporal

Dados de 2022 apenas - não captura tendências históricas ou projeções futuras

Composição Gravimétrica

Não detalha orgânicos vs recicláveis vs rejeitos (PNRS Art. 9º)

Validação de Campo

Estimativas não validadas com dados reais de coleta municipal

⚠️ Desafios Enfrentados

1. IBGE API Instável

Problema: Timeouts frequentes, erros 500, respostas vazias

Solução: Sistema de 3 camadas (projeções → agregados → cálculo local)

Aprendizado: Sempre ter fallback para APIs externas

2. Tamanho Inicial dos Mapas (40 MB)

Problema: Inviável para GitHub Pages, lento para carregar

Solução: Simplificação de geometrias (tolerância 100m em EPSG:3857)

Aprendizado: Sempre projetar para CRS métrico antes de simplificar

3. Bug da Legenda Desaparecendo

Problema: Legenda não aparecia após refatoração

Causa: Uso de m.get_root().add_child() ao invés de m.get_root().html.add_child()

Aprendizado: Documentação Folium incompleta - necessário experimentação

4. Download de Ottobacias (1 GB via API)

Problema: API ANA lenta, às vezes offline

Solução: Dual-source pattern (arquivo local → API fallback)

Aprendizado: Sempre oferecer opção de dados locais
